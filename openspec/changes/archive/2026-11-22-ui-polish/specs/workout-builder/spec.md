## MODIFIED Requirements

### Requirement: UI управления тренировками
Экран «Тренировки» SHALL показывать список шаблонов (название, число упражнений, дата последнего выполнения), кнопку создания и переход к просмотру тренировки, а из просмотра — к редактору. Редактор SHALL позволять задать название, описание, добавить/удалить упражнение, изменить порядок кнопками «вверх/вниз», ввести плановые подходы, повторы, вес (кг), отдых (сек) и заметки, сохранить одним действием и удалить тренировку с подтверждением, сообщающим об архивировании при наличии истории. Ошибки валидации сервера MUST отображаться пользователю.

#### Scenario: Создание через UI
- **WHEN** пользователь заполняет название и одно упражнение и нажимает «Сохранить»
- **THEN** тренировка появляется в списке «Тренировки»

#### Scenario: Пустой список
- **WHEN** тренировок нет
- **THEN** отображается пустое состояние с кнопкой «Создать тренировку»

## ADDED Requirements

### Requirement: Просмотр тренировки
Открытие тренировки из списка SHALL показывать экран просмотра без полей ввода: название, описание, упражнения по порядку с названием, плановыми подходами, повторами, весом, отдыхом, описанием и заметками. Экран просмотра SHALL предлагать «Начать» и «Редактировать»; редактирование открывается отдельным экраном, после сохранения пользователь возвращается к просмотру. Архивная тренировка MUST показываться только в режиме просмотра с пометкой об архиве, без кнопок «Начать» и «Редактировать».

#### Scenario: Открытие шаблона
- **WHEN** пользователь нажимает на тренировку в списке «Тренировки»
- **THEN** открывается просмотр с полным текстом упражнений и кнопками «Начать» и «Редактировать»

#### Scenario: Сохранение после редактирования
- **WHEN** пользователь нажимает «Редактировать», меняет упражнение и сохраняет
- **THEN** открывается просмотр этой тренировки с изменёнными данными

#### Scenario: Архивная тренировка
- **WHEN** пользователь открывает архивную тренировку
- **THEN** показан просмотр с пометкой об архиве, кнопок «Начать» и «Редактировать» нет

### Requirement: Полное отображение пользовательского текста
Названия, описания и заметки SHALL отображаться полностью на всех экранах: текст переносится по строкам, включая длинные слова без пробелов, переводы строк в описаниях и заметках сохраняются. В формах многострочные поля MUST увеличиваться по высоте под введённый текст без внутренней прокрутки, а поля названий MUST переносить длинное название на несколько строк, не допуская ввода перевода строки.

#### Scenario: Длинное название упражнения на мобильном
- **WHEN** в редакторе на экране шириной 375 px введено название упражнения длиннее ширины поля
- **THEN** название видно целиком на нескольких строках, горизонтальной обрезки нет

#### Scenario: Длинное описание
- **WHEN** в описание упражнения вставлен текст из нескольких абзацев
- **THEN** поле растягивается под весь текст, и прокручивать его внутри не нужно

#### Scenario: Перевод строки в названии
- **WHEN** пользователь нажимает Enter в поле названия
- **THEN** перевод строки не добавляется
