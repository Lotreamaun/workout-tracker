## Purpose

Выполнение тренировки по шаблону: запуск сессии, запись фактических результатов подходов, таймер отдыха и завершение без изменения исходного плана.

## ADDED Requirements

### Requirement: Запуск сессии
`POST /api/workouts/:id/sessions` SHALL создавать сессию со статусом `in_progress`, `startedAt` = текущее время UTC, `workoutNameSnapshot` = название шаблона, и для каждого упражнения создавать `plannedSets` подходов с snapshot: название упражнения, позиция, номер подхода (с 1), плановые повторы и вес, отдых. Ответ 201 — детали сессии (см. «Детали сессии»).

#### Scenario: Успешный запуск
- **WHEN** у шаблона упражнения «Присед» (3 подхода по 8 × 80) и «Жим» (2 подхода)
- **THEN** создаётся сессия с 2 упражнениями: у «Присед» 3 подхода с `plannedReps: 8`, `plannedWeight: 80`, `actualReps: null`, `isCompleted: false`; у «Жим» 2 подхода

#### Scenario: Уже есть активная сессия
- **WHEN** существует сессия со статусом `in_progress`
- **THEN** ответ 409 `SESSION_IN_PROGRESS`, `details.sessionId` — id активной сессии, новая сессия не создаётся

#### Scenario: Архивный или пустой шаблон
- **WHEN** шаблон архивирован или не содержит упражнений
- **THEN** ответ 409 с кодом `WORKOUT_ARCHIVED` или `WORKOUT_EMPTY` соответственно

### Requirement: Детали сессии
`GET /api/sessions/:id` SHALL возвращать `{ id, workoutId, workoutNameSnapshot, status, startedAt, completedAt, notes, exercises: [{ workoutExerciseId, exercisePosition, name, restSeconds, isSkipped, sets: [{ id, setNumber, plannedReps, actualReps, plannedWeight, actualWeight, rpe, isCompleted, completedAt, notes }] }] }`, упражнения по позиции, подходы по номеру. Неизвестный id — 404 `NOT_FOUND`.

#### Scenario: Плановое и фактическое раздельно
- **WHEN** запрашивается сессия с заполненными фактическими значениями
- **THEN** каждый подход содержит одновременно плановые и фактические поля

### Requirement: Обновление результатов
`PATCH /api/sessions/:id` SHALL принимать `{ notes?, status?: "abandoned", sets?: [{ id, actualReps?, actualWeight?, rpe?, isCompleted?, notes? }], exercises?: [{ exercisePosition, isSkipped }] }` и возвращать детали сессии. При `isCompleted: true` сервер MUST устанавливать `completedAt` подхода (если не установлен), при `false` — обнулять. Ограничения: `actualReps` целое 0..1000, `actualWeight` 0..2000, `rpe` 1..10 с шагом 0.5, notes ≤ 2000; id подхода другой сессии — 400 `VALIDATION_ERROR`. Сессия со статусом `abandoned` MUST NOT изменяться (409 `SESSION_NOT_EDITABLE`); завершённую сессию можно исправлять, но не переводить в `abandoned`. Обновление MUST NOT изменять шаблон тренировки.

#### Scenario: Отметка подхода
- **WHEN** клиент отправляет `{ "sets": [{ "id": "<s1>", "actualReps": 8, "actualWeight": 82.5, "rpe": 8, "isCompleted": true }] }`
- **THEN** подход сохраняет значения, `isCompleted: true`, `completedAt` установлен; плановые значения шаблона не изменились

#### Scenario: Пропуск упражнения
- **WHEN** клиент отправляет `{ "exercises": [{ "exercisePosition": 1, "isSkipped": true }] }`
- **THEN** упражнение с позицией 1 отмечено `isSkipped: true`

#### Scenario: Некорректный RPE
- **WHEN** `rpe` равен 11 или 7.3
- **THEN** ответ 400 `VALIDATION_ERROR`

#### Scenario: Отмена сессии
- **WHEN** клиент отправляет `{ "status": "abandoned" }` для сессии `in_progress`
- **THEN** статус становится `abandoned`, можно запустить новую сессию

### Requirement: Завершение сессии
`POST /api/sessions/:id/complete` с необязательным `{ notes? }` SHALL переводить сессию `in_progress` в `completed` и устанавливать `completedAt`. Для сессии в другом статусе — 409 `SESSION_NOT_IN_PROGRESS`.

#### Scenario: Завершение
- **WHEN** пользователь завершает активную сессию
- **THEN** статус `completed`, `completedAt` установлен, `lastPerformedAt` шаблона в списке тренировок равен этому времени

### Requirement: Экран активной тренировки
Экран `/sessions/:id` SHALL показывать карточки упражнений с подходами, где плановые значения визуально отличаются от фактических; ввод повторов, веса и RPE с числовой клавиатурой; крупную кнопку отметки подхода; пропуск упражнения; заметки; кнопки «Завершить» и «Отменить тренировку» с подтверждением. При отметке подхода с пустыми фактическими значениями интерфейс MUST подставлять плановые. Изменения MUST сохраняться на сервере без отдельной кнопки сохранения.

#### Scenario: Быстрая отметка
- **WHEN** пользователь нажимает отметку подхода с плановыми 8 × 80, не вводя значений
- **THEN** подход сохраняется как выполненный с `actualReps: 8`, `actualWeight: 80`

### Requirement: Таймер отдыха
После отметки подхода интерфейс SHALL запускать таймер отдыха на `restSeconds` упражнения (если задан), с возможностью добавить 15 секунд, пропустить и запустить вручную. Оставшееся время MUST вычисляться от целевого timestamp окончания, сохраняться при перезагрузке страницы в пределах устройства и корректно отображаться после возврата из фона. По окончании — визуальная индикация и вибрация, если API доступен; фоновая работа на iOS не гарантируется.

#### Scenario: Возврат из фона
- **WHEN** таймер на 120 с запущен, приложение свёрнуто на 60 с и открыто снова
- **THEN** отображается около 60 с оставшегося времени

### Requirement: Главная
Главная SHALL показывать активную сессию с кнопкой «Продолжить» (если есть), список тренировок для быстрого запуска и последние 5 завершённых занятий. Попытка запуска при активной сессии MUST предлагать перейти к ней.

#### Scenario: Есть активная сессия
- **WHEN** у пользователя есть сессия `in_progress`
- **THEN** Главная показывает её название и кнопку «Продолжить», ведущую на `/sessions/:id`
