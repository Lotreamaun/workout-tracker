## Context

Общий таймер использует абсолютный срок и хранит его локально. В фоновой вкладке JavaScript может остановиться. Нативный Web Push доступен PWA с домашнего экрана с iOS 16.4 и запрашивается при прямом действии пользователя. [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

## Goals / Non-Goals

- Доставлять системное уведомление именно об окончании отдыха. Сохранить встроенное уведомление и визуальную индикацию.
- Существующий Fastify-процесс отправляет Web Push. Состояние доставки хранится в SQLite. Данные таймера интерфейса остаются в действующем локальном хранилище.
- Область поддержки этой версии — iPhone. Работа платформ определяется наличием Web Push и адресом подписки Apple.

## Decisions

### API

Все маршруты идут через существующий клиент API с действующим ключом. Схемы Zod валидируют вход. Контракт позволяет разрабатывать веб и сервер независимо.

| Метод и путь | Запрос | Успешный ответ |
|---|---|---|
| GET /api/rest-push/config | — | 200 `{ publicKey: string \| null }` |
| POST /api/rest-push/subscriptions | `{ endpoint, keys: { p256dh, auth } }` | 200 `{ id: string }` |
| PATCH /api/rest-push/subscriptions/:id/timer | `{ sessionId: string, endsAt: string \| null, revision: number }` | 204 |
| DELETE /api/rest-push/subscriptions/:id | — | 204, в том числе при повторе |

Идентификаторы — UUID. Ненулевой срок — UTC ISO 8601, в будущем и не дальше 24 часов. Установка срока требует сессию `in_progress`. Отмена по `null` применяется к совпадающей сессии. Ревизия — положительное безопасное целое, возрастающее для каждой установки и сохраняемое при перезагрузке. Повтор ревизии и более ранние запросы ничего не меняют. Повтор уже обработанного срока не создаёт повторную отправку. POST на тот же endpoint обновляет подписку и возвращает прежний ID. Отсутствующая подписка при PATCH — 404, завершённая сессия при установке срока — 409. CRUD подписки включается лишь при наличии конфигурации и действующей защиты API. Отключённый сервер возвращает `publicKey: null`, операции записи — 503.

### Сервер

- Конфигурация `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` и `VAPID_SUBJECT`. Шифрование и подпись поручаются библиотеке `web-push`. Допустим HTTPS на поддомене `push.apple.com` без нестандартного порта и userinfo. Ограничиваются размеры входных полей, переходы по перенаправлениям отключены. Тела запросов, ключи и полные endpoint не пишутся в логи.
- В SQLite хранится одна подписка на endpoint и один возможный срок на подписку. Миграцию генерирует Drizzle Kit. Сервер атомарно сверяет актуальность срока и статус сессии непосредственно перед началом исходящего запроса. Захват срока — граница отмены. Отдельно захватывается только тот срок, по которому отправка начинается сразу. Повтор того же срока не должен заново ставить уже отправленное уведомление. Изменение подписки после отправки учитывается при очистке по ответу 404/410.
- Цикл с коротким интервалом запускается вместе с Fastify только при включённой конфигурации, при закрытии прекращает брать задачи и дожидается текущей отправки до закрытия SQLite. Запуски цикла не пересекаются. Job истекает через 30 секунд от срока, TTL отправки ограничен оставшимся временем. У запроса короткий таймаут и заголовок `Urgency: high`. Проверить, что JWT VAPID переиспользуется для каждого origin по требованиям Apple. [Документация Apple](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers) В payload только `{ type: 'rest-ended', sessionId }`. Реальная доставка в тестах заменяется передаваемой функцией.

### Веб

- Русскоязычное управление на экране активной тренировки. Готовность service worker и публичного ключа устанавливается до нажатия; подписка с разрешением начинается непосредственно в обработчике нажатия. Состояние «включено» появляется после регистрации на сервере и сверки браузерной подписки, разрешения и публичного ключа. Отзыв разрешения, смена ключа и ответ 404 при обновлении таймера переводят управление в состояние повторного подключения. При отключении, если сервер недоступен, интерфейс сообщает об ошибке и позволяет повторить.
- Общий таймер передаёт серверу обновления при старте, продлении и пропуске, независимо от маршрута. Запросы с одной установки упорядочиваются, а сервер отклоняет запоздалые изменения по ревизии. Включение в ходе отдыха ставит оставшийся срок. Естественное истечение локального таймера не отменяет запланированную отправку. Функция уведомлений не блокирует запись подходов и отсчёт.
- Сохранить действующую сборку PWA и добавить обработчики `push` и `notificationclick`. Worker показывает системное уведомление сразу после получения push, в том числе при открытом PWA. Для перехода он строит из проверенного UUID локальный маршрут `/sessions/:id`. Роутинг и текущая политика сетевых запросов API сохраняются.

## Risks / Trade-offs

- После захвата задачи сбой процесса или сети может потерять одну отправку. Отправленный Apple Push отозвать нельзя. Короткий TTL ограничивает опоздавшие уведомления.
- Абсолютный срок рассчитывается по часам iPhone. Для проверки часы устройства и сервера должны идти синхронно.
- Настройки iOS, «Фокусирование» и сеть влияют на показ. После смены VAPID-ключей требуется повторная подписка. Для нового запуска потребуется доступ сервера к `*.push.apple.com`.
- Если изменение таймера не дошло до сервера, принятый ранее срок может дать уведомление. Интерфейс показывает сбой синхронизации; при неработающей сети локальный таймер остаётся доступным.

## Migration Plan

1. Обновить сборку API и PWA. Сервер применяет миграцию при старте.
2. Добавить стабильную пару VAPID-ключей и контакт VAPID в окружение сервера с `API_TOKEN`. Раздавать приложение по HTTPS.
3. Для отключения убрать настройку VAPID и перезапустить сервер. Миграция добавляет отдельную таблицу.
4. На iPhone открыть установленное PWA, включить уведомления, запустить отдых и заблокировать экран. Проверить получение, переход в тренировку, продление и пропуск.
