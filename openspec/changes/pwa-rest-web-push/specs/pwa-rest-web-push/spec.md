## Purpose

Уведомлять пользователя об окончании отдыха во время тренировки, пока PWA на iPhone свёрнуто или экран заблокирован.

## ADDED Requirements

### Requirement: Подписка на устройстве

Установленное на домашний экран iPhone PWA по HTTPS SHALL предлагать включение Web Push на iOS 16.4 и новее при поддержке платформой и настройке сервера. Запрос разрешения MUST происходить по нажатию пользователя. Приложение SHALL показывать результат и позволять отключить подписку на текущей установке. Таймер MUST работать при отказе, отсутствии поддержки и недоступности сервиса уведомлений.

#### Scenario: Подключение на iPhone

- **WHEN** пользователь открывает PWA с домашнего экрана, нажимает «Включить уведомления» и даёт разрешение
- **THEN** приложение подключает уведомления на этой установке и показывает, что их можно отключить

#### Scenario: Отказ или отсутствие поддержки

- **WHEN** пользователь отклоняет запрос или среда не поддерживает Web Push
- **THEN** таймер отдыха продолжает работать с прежней визуальной индикацией, а интерфейс объясняет, почему уведомления недоступны

### Requirement: Доставка об окончании отдыха

Пока подписка включена, приложение SHALL передавать серверу время окончания при запуске, перезапуске и продлении отдыха. Сервер SHALL выполнить одну попытку отправки для принятого актуального таймера вскоре после истечения срока, включая случай, когда PWA в фоне. Принятый сервером пропуск, выключение уведомлений, завершение или отмена тренировки MUST отменять будущую отправку. Приложение MUST сохранять обычное поведение таймера, если отправить изменения на сервер не удалось.

#### Scenario: Экран заблокирован

- **WHEN** сервер принял время окончания активного отдыха, а iPhone заблокирован
- **THEN** сервер отправляет Web Push по истечении таймера, и PWA показывает «Отдых окончен», если доставка разрешена системой

#### Scenario: Продление, замена или отмена до отправки

- **WHEN** сервер до отправки принял продление, новый срок, пропуск, выключение уведомлений, завершение или отмену
- **THEN** Push по прежнему сроку не отправляется

#### Scenario: Запоздалое изменение

- **WHEN** сервер после более свежего изменения получает запоздалый запрос от той же установки
- **THEN** сервер сохраняет актуальное состояние таймера

#### Scenario: Возврат к тренировке

- **WHEN** пользователь нажимает системное уведомление
- **THEN** PWA открывает маршрут соответствующей тренировки

#### Scenario: Короткий перезапуск сервера

- **WHEN** API перезапущен после принятия расписания и снова работает до истечения срока
- **THEN** ожидающее уведомление сохраняется и отправляется по прежнему времени

### Requirement: Защита подписки

API уведомлений MUST использовать существующий общий ключ доступа. Сервер SHALL отправлять только на проверенные HTTPS-адреса сервиса Web Push Apple. Закрытый ключ MUST храниться на сервере, а данные подписки MUST исключаться из журналов.

#### Scenario: Неподходящий адрес доставки

- **WHEN** клиент передаёт URL за пределами сервиса Web Push Apple
- **THEN** API отклоняет подписку без исходящего запроса
