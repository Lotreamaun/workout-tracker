# exercise-description-everywhere Specification

## Purpose
Описание упражнения доступно не только при просмотре шаблона тренировки, но и во время выполнения сессии, и в карточке библиотеки «Упражнения».

## Requirements

### Requirement: Описание в ответах библиотеки упражнений
`GET /api/exercises` и `GET /api/exercises/:id` SHALL возвращать поле `description` (строка | null) для каждого упражнения библиотеки. Значение берётся из того шаблона, в котором упражнение появилось первым; редактирование описания в другом шаблоне с тем же нормализованным названием не меняет уже созданную запись библиотеки.

#### Scenario: Первое появление определяет описание
- **WHEN** создаётся тренировка с упражнением «Жим лёжа» и описанием «Лежа на скамье, гриф на груди», а затем вторая тренировка с упражнением «жим лежа» и другим описанием
- **THEN** в библиотеке одна запись «Жим лёжа», и её `description` — описание из первой тренировки

### Requirement: Описание в снэпшоте сессии
`POST /api/workouts/:id/sessions` SHALL фиксировать `description` каждого упражнения шаблона в снэпшоте сессии; `GET /api/sessions/:id` SHALL отдавать `exercises[].description`. Изменение описания в шаблоне после запуска сессии MUST NOT менять снэпшот существующей сессии.

#### Scenario: Снэпшот сессии не зависит от правки шаблона
- **WHEN** шаблон с упражнением с описанием запущен в сессию, а затем описание в шаблоне изменено
- **THEN** детали сессии по-прежнему содержат исходное описание упражнения

### Requirement: Описание в интерфейсе
Карточка упражнения в разделе «Упражнения» (`/exercises`) SHALL показывать описание под названием, если оно задано. `ExerciseDetailPage` SHALL показывать описание под названием упражнения. `ExerciseCard` на активной сессии SHALL показывать описание под названием (если задано), не перекрывая элементы ввода подходов.

#### Scenario: Описание в карточке библиотеки
- **WHEN** в библиотеке есть упражнение с описанием, пользователь открывает `/exercises`
- **THEN** в карточке этого упражнения описание видно под названием
