# exercise-library Specification

## Purpose
Библиотека упражнений, которая пополняется сама из шаблонов, и медиа (картинки, GIF, видео) с техникой выполнения, общие для всех шаблонов с одноимённым упражнением.
## Requirements
### Requirement: Автопополнение библиотеки
Упражнение библиотеки SHALL однозначно определяться нормализованным названием: обрезка пробелов по краям, схлопывание повторяющихся пробелов, нижний регистр, замена «ё» на «е». При создании и изменении шаблона, а также при импорте тренировок сервер MUST добавлять в библиотеку каждое название упражнения, которого там ещё нет; отображаемое название берётся из первого появления. При старте api MUST добавлять в библиотеку названия упражнений всех существующих шаблонов. Пополнение MUST выполняться в той же транзакции, что и сохранение шаблона. Удаление шаблона или упражнения из шаблона MUST NOT удалять запись библиотеки.

#### Scenario: Новое упражнение в шаблоне
- **WHEN** сохраняется шаблон с упражнением «Жим лёжа», которого нет в библиотеке
- **THEN** в библиотеке появляется упражнение «Жим лёжа»

#### Scenario: Совпадение по нормализованному названию
- **WHEN** в библиотеке есть «Жим лёжа», а сохраняется шаблон с упражнением « жим  лежа »
- **THEN** новая запись не создаётся, упражнение шаблона связано с «Жим лёжа»

### Requirement: Список и карточка упражнения
`GET /api/exercises` SHALL возвращать все упражнения библиотеки, отсортированные по названию (без учёта регистра, русская локаль). Каждое упражнение — `{ id, name, media: ExerciseMedia[] }`. `GET /api/exercises/:id` SHALL возвращать одно упражнение; неизвестный id MUST давать 404 `NOT_FOUND`. `ExerciseMedia` = `{ id, kind: "image" | "video", url, thumbUrl }`, где `url` и `thumbUrl` — пути от корня сайта (`/media/...`). Медиа MUST идти в порядке добавления.

#### Scenario: Упражнение с медиа
- **WHEN** к упражнению загружены картинка и GIF
- **THEN** ответ содержит два элемента `media`: первый с `kind: "image"`, второй с `kind: "video"`

### Requirement: Загрузка медиа
`POST /api/exercises/:id/media` SHALL принимать `multipart/form-data` с одним файлом в поле `file` и возвращать 201 с обновлённым упражнением. Тип файла MUST определяться по содержимому, а не по имени или заявленному MIME. Поддерживаются JPEG, PNG, WebP (статичный), GIF, MP4, MOV, WebM.
- Картинки MUST сохраняться как WebP, большая сторона не больше 1280 px, ориентация по EXIF.
- GIF и видео MUST сохраняться как MP4 H.264 без звука, большая сторона не больше 720 px, длительность не больше 60 с (лишнее обрезается), частота кадров не больше 30, с быстрым стартом воспроизведения.
- Для каждого медиа MUST создаваться квадратная миниатюра WebP.

Ошибки:
- неизвестное упражнение → 404 `NOT_FOUND`;
- у упражнения уже 5 медиа → 409 `MEDIA_LIMIT_REACHED`;
- файл больше 100 МБ → 413 `MEDIA_TOO_LARGE`;
- нет файла или формат не поддерживается → 415 `MEDIA_UNSUPPORTED`;
- файл не удалось обработать → 422 `MEDIA_PROCESSING_FAILED`.

При любой ошибке MUST NOT оставаться записи в БД и файлов. Лимит в 5 медиа MUST соблюдаться и при параллельных загрузках.

#### Scenario: Загрузка GIF
- **WHEN** к упражнению загружается анимированный GIF
- **THEN** ответ 201, новое медиа имеет `kind: "video"`, по `url` отдаётся MP4, по `thumbUrl` — WebP

#### Scenario: Загрузка фото
- **WHEN** загружается JPEG 4000×3000
- **THEN** новое медиа имеет `kind: "image"`, по `url` отдаётся WebP размером 1280×960

#### Scenario: Шестой файл
- **WHEN** у упражнения уже 5 медиа и загружается ещё один файл
- **THEN** ответ 409 `MEDIA_LIMIT_REACHED`, медиа не добавляется

#### Scenario: Неподдерживаемый файл
- **WHEN** загружается PDF или текстовый файл, переименованный в `.gif`
- **THEN** ответ 415 `MEDIA_UNSUPPORTED`, ничего не сохраняется

#### Scenario: Слишком большой файл
- **WHEN** загружается файл больше 100 МБ
- **THEN** ответ 413 `MEDIA_TOO_LARGE`, ничего не сохраняется

### Requirement: Удаление медиа и упражнения
`DELETE /api/exercises/:id/media/:mediaId` SHALL удалять медиа и его файлы и возвращать 200 с обновлённым упражнением. Медиа другого упражнения или неизвестный id MUST давать 404 `NOT_FOUND`. `DELETE /api/exercises/:id` SHALL удалять упражнение библиотеки со всеми медиа и файлами и возвращать 204; шаблоны и сессии MUST NOT меняться. Если упражнение с таким названием остаётся в шаблонах, оно снова появится в библиотеке без медиа при следующем пополнении.

#### Scenario: Удаление медиа
- **WHEN** удаляется одно из двух медиа упражнения
- **THEN** ответ содержит одно медиа, а файлы удалённого больше не отдаются (404)

#### Scenario: Удаление упражнения библиотеки
- **WHEN** удаляется упражнение библиотеки, которое используется в шаблоне
- **THEN** ответ 204, шаблон не изменился, его упражнение отдаётся с `media: []`

### Requirement: Раздача файлов медиа
Сервер SHALL отдавать файлы медиа по `GET /media/<файл>` с правильным `Content-Type`, поддержкой Range-запросов (нужны для видео в Safari) и `Cache-Control: public, max-age=31536000, immutable`. Неизвестный файл MUST давать 404, а не страницу приложения. Временные файлы обработки MUST NOT быть доступны по HTTP.

#### Scenario: Range-запрос видео
- **WHEN** браузер запрашивает MP4 с заголовком `Range: bytes=0-1`
- **THEN** ответ 206 с двумя байтами

#### Scenario: Неизвестный файл
- **WHEN** запрашивается `/media/unknown.mp4`
- **THEN** ответ 404

### Requirement: Экран библиотеки
Интерфейс SHALL иметь экран «Упражнения» (`/exercises`) со списком упражнений библиотеки: миниатюра первого медиа или заглушка, название, число медиа. Над списком — поле поиска, которое фильтрует по нормализованному названию без запроса к серверу. Нажатие на упражнение MUST открывать его карточку (`/exercises/:id`). Пустая библиотека MUST показывать пояснение, что упражнения появятся из тренировок.

#### Scenario: Поиск
- **WHEN** пользователь вводит «жим» в поиске
- **THEN** в списке остаются только упражнения, в нормализованном названии которых есть «жим»

### Requirement: Управление медиа в карточке упражнения
Карточка упражнения SHALL показывать медиа сеткой квадратных миниатюр (у видео — значок воспроизведения) и счётчик «N из 5».
- Пока медиа меньше 5, MUST быть плитка «Добавить», которая открывает выбор файлов (фото, видео, несколько файлов сразу).
- Клиент MUST заранее отклонять файлы больше 100 МБ и файлы сверх лимита, показывая понятное сообщение.
- Выбранные файлы загружаются по очереди; на время загрузки и сжатия на месте каждого файла показывается плитка с индикатором «Сжатие…».
- Ошибка одного файла MUST показываться сообщением и не отменять остальные.
- У каждой миниатюры MUST быть кнопка удаления с областью нажатия не меньше 44×44 px и подтверждением.
- Нажатие на миниатюру открывает просмотрщик.
- В карточке MUST быть удаление упражнения из библиотеки с подтверждением.

#### Scenario: Загрузка нескольких файлов
- **WHEN** у упражнения 3 медиа, а пользователь выбирает 2 GIF
- **THEN** появляются две плитки «Сжатие…»; после обработки отображаются 5 миниатюр, плитка «Добавить» исчезает

#### Scenario: Выбор лишних файлов
- **WHEN** у упражнения 4 медиа, а пользователь выбирает 3 файла
- **THEN** загружается первый файл, для остальных показывается сообщение о лимите 5 медиа

### Requirement: Просмотрщик медиа
Просмотрщик SHALL открываться на весь экран на выбранном медиа и листать медиа упражнения горизонтальным свайпом; на десктопе — также кнопками и стрелками клавиатуры. Он показывает счётчик «2 / 5» и кнопку закрытия, закрывается по Escape и кнопке «Назад» системы не ломает навигацию. Картинки MUST вписываться в экран без обрезки. Видео MUST воспроизводиться автоматически, без звука, по кругу, встроенно (без перехода в системный плеер iOS).

#### Scenario: Открытие GIF во время тренировки
- **WHEN** пользователь нажимает на миниатюру GIF в карточке упражнения сессии
- **THEN** открывается просмотрщик, и анимация воспроизводится по кругу
