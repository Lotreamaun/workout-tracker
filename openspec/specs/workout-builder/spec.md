# workout-builder Specification

## Purpose
Управление шаблонами тренировок: план занятия с упорядоченными упражнениями и плановыми параметрами, которые затем используются для запуска сессий.
## Requirements
### Requirement: Создание тренировки
Система SHALL создавать шаблон по `POST /api/workouts` с телом `{ name, description?, exercises?: ExerciseInput[] }` и возвращать 201 с полным объектом тренировки. `ExerciseInput` = `{ name, description?, plannedSets, plannedReps?, plannedWeight?, restSeconds?, notes? }`. Порядок упражнений MUST определяться порядком элементов массива (position 0..n-1). ID и даты MUST генерироваться сервером (UUID, ISO 8601 UTC).

#### Scenario: Создание с упражнениями
- **WHEN** клиент отправляет `{ "name": "Ноги", "exercises": [{ "name": "Присед", "plannedSets": 3, "plannedReps": 8, "plannedWeight": 80, "restSeconds": 120 }] }`
- **THEN** ответ 201 содержит `id`, `name`, `description: null`, `archivedAt: null`, `createdAt`, `updatedAt` и `exercises` с одним элементом, у которого есть `id` и `position: 0`

#### Scenario: Пустое имя
- **WHEN** `name` пустой или состоит только из пробелов
- **THEN** ответ 400 `VALIDATION_ERROR`, ничего не создаётся

### Requirement: Ограничения полей
Сервер MUST отклонять с `VALIDATION_ERROR`: name тренировки или упражнения длиннее 120 символов или пустой после trim; description/notes длиннее 2000; `plannedSets` не целое или вне 1..50; `plannedReps` не целое или вне 1..1000; `plannedWeight` вне 0..2000; `restSeconds` не целое или вне 0..3600; более 50 упражнений; неизвестные поля в теле.

#### Scenario: Некорректное число подходов
- **WHEN** упражнение имеет `plannedSets: 0`
- **THEN** ответ 400 `VALIDATION_ERROR` с указанием поля в `details`

### Requirement: Список тренировок
`GET /api/workouts` SHALL возвращать неархивированные шаблоны, отсортированные по `updatedAt` по убыванию, каждый с `id`, `name`, `description`, `exerciseCount`, `lastPerformedAt` (время завершения последней completed-сессии или null), `createdAt`, `updatedAt`.

#### Scenario: Архивированные скрыты
- **WHEN** есть одна активная и одна архивированная тренировка
- **THEN** список содержит только активную

### Requirement: Получение тренировки
`GET /api/workouts/:id` SHALL возвращать тренировку с упражнениями, отсортированными по `position`, включая архивированную (с заполненным `archivedAt`). Несуществующий id MUST давать 404 `NOT_FOUND`.

#### Scenario: Несуществующая тренировка
- **WHEN** запрашивается неизвестный id
- **THEN** ответ 404 с `error.code` `NOT_FOUND`

### Requirement: Изменение тренировки
`PATCH /api/workouts/:id` SHALL принимать `{ name?, description?, exercises? }` и возвращать обновлённую тренировку. Если передан `exercises`, он MUST трактоваться как полный упорядоченный список: элементы с `id` существующего упражнения этой тренировки обновляются, элементы без `id` создаются, отсутствующие упражнения удаляются, `position` пересчитывается по порядку массива. `id`, не принадлежащий этой тренировке, MUST давать 400 `VALIDATION_ERROR`. Изменение MUST выполняться атомарно и обновлять `updatedAt`. Изменение архивированной тренировки MUST давать 409 `WORKOUT_ARCHIVED`.

#### Scenario: Смена порядка
- **WHEN** тренировка имеет упражнения A (position 0) и B (position 1), а клиент отправляет `exercises: [B, A]` с их id
- **THEN** у B `position: 0`, у A `position: 1`, id упражнений не изменились

#### Scenario: Удаление упражнения из плана
- **WHEN** клиент отправляет `exercises` без одного из существующих упражнений
- **THEN** это упражнение удаляется из шаблона, а ранее записанные подходы прошлых сессий остаются в истории неизменными

#### Scenario: Чужой id упражнения
- **WHEN** в `exercises` передан id упражнения другой тренировки
- **THEN** ответ 400 `VALIDATION_ERROR`, данные не меняются

### Requirement: Удаление или архивирование
`DELETE /api/workouts/:id` SHALL физически удалять шаблон и его упражнения, если по нему нет ни одной сессии, и архивировать его (устанавливать `archivedAt`), если сессии есть. Ответ 200 `{ "result": "deleted" | "archived" }`. Сессии и подходы истории MUST NOT удаляться.

#### Scenario: Удаление без истории
- **WHEN** у тренировки нет сессий
- **THEN** ответ `{ "result": "deleted" }`, последующий GET даёт 404

#### Scenario: Архивирование при наличии истории
- **WHEN** у тренировки есть завершённая сессия
- **THEN** ответ `{ "result": "archived" }`, тренировка исчезает из списка, сессия доступна в истории без изменений

### Requirement: UI управления тренировками
Экран «Тренировки» SHALL показывать список шаблонов (название, число упражнений, дата последнего выполнения), кнопку создания и переход к редактору. Редактор SHALL позволять задать название, описание, добавить/удалить упражнение, изменить порядок кнопками «вверх/вниз», ввести плановые подходы, повторы, вес (кг), отдых (сек) и заметки, сохранить одним действием и удалить тренировку с подтверждением, сообщающим об архивировании при наличии истории. Ошибки валидации сервера MUST отображаться пользователю.

#### Scenario: Создание через UI
- **WHEN** пользователь заполняет название и одно упражнение и нажимает «Сохранить»
- **THEN** тренировка появляется в списке «Тренировки»

#### Scenario: Пустой список
- **WHEN** тренировок нет
- **THEN** отображается пустое состояние с кнопкой «Создать тренировку»
