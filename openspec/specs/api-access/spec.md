# api-access Specification

## Purpose
Защищает персональные данные и загрузку файлов на публичном домене одним общим ключом доступа, без пользователей и логина.
## Requirements
### Requirement: Ключ доступа к API
Если на сервере задана переменная окружения `API_TOKEN`, каждый запрос к `/api/*`, кроме `GET /api/health` и CORS preflight (`OPTIONS`), MUST содержать заголовок `Authorization: Bearer <API_TOKEN>`. Отсутствующий или неверный ключ MUST давать 401 `{ error: { code: "UNAUTHORIZED", message } }` до валидации и до выполнения обработчика. Сравнение ключа MUST выполняться за постоянное время. Если `API_TOKEN` не задан, проверка выключена, а сервер MUST при старте писать в лог предупреждение. Файлы `/media/*` ключа не требуют: их адреса содержат случайные UUID.

#### Scenario: Запрос без ключа
- **WHEN** `API_TOKEN` задан, а клиент выполняет `GET /api/workouts` без заголовка `Authorization`
- **THEN** ответ 401 с `error.code` `UNAUTHORIZED`

#### Scenario: Неверный ключ при записи
- **WHEN** `API_TOKEN` задан, а клиент отправляет `POST /api/workouts` с неверным ключом
- **THEN** ответ 401 `UNAUTHORIZED`, тренировка не создаётся

#### Scenario: Верный ключ
- **WHEN** клиент передаёт `Authorization: Bearer <API_TOKEN>`
- **THEN** запрос обрабатывается как обычно

#### Scenario: Health-check открыт
- **WHEN** `API_TOKEN` задан, а клиент запрашивает `GET /api/health` без ключа
- **THEN** ответ 200

#### Scenario: Защита выключена
- **WHEN** `API_TOKEN` не задан
- **THEN** все запросы обрабатываются без заголовка `Authorization`

### Requirement: Ввод ключа в интерфейсе
Клиент SHALL передавать сохранённый на устройстве ключ в каждом запросе к API. При ответе 401 `UNAUTHORIZED` интерфейс MUST показать диалог ввода ключа: поле скрытого ввода, кнопку «Сохранить» и пояснение, что ключ задаётся на сервере. После сохранения ключ MUST храниться на устройстве, а данные текущего экрана MUST перезапрашиваться без перезагрузки страницы. Если сохранённый ключ неверен, диалог MUST появиться снова.

#### Scenario: Первый запуск на новом устройстве
- **WHEN** пользователь открывает приложение без сохранённого ключа, а сервер требует ключ
- **THEN** появляется диалог ввода ключа; после ввода верного ключа экран загружает данные

#### Scenario: Ключ запоминается
- **WHEN** пользователь ввёл верный ключ и перезапустил приложение
- **THEN** диалог не появляется, данные загружаются
